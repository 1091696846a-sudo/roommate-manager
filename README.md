# 项目名称：roommate-manager

「合租生活管家」项目介绍
这个项目是什么
这是一个面向 2 到 6 人合租场景的轻量工具，把合租中最容易引发矛盾的四个高频问题收进同一个页面：钱怎么分、活怎么排、东西怎么续、规矩怎么定。它最初设计为 React 加 Supabase 的多端同步应用，最终落地为一个单文件 HTML 应用，不依赖服务器、不依赖安装、不依赖网络，打开就能用，也可以托管到任意静态平台获得在线地址。

用了什么语言与技术
结构上用的是 HTML5，单一文档配合语义化容器，并通过自定义的 data-action 属性标记可交互元素。样式上用的是原生 CSS3，包括 Flex 布局、移动端安全区适配 env(safe-area-inset-*)，以及导航栏的 backdrop-filter 毛玻璃效果。逻辑上用的是原生 JavaScript，采用 ES5 风格写法，用立即执行函数封装，不引入任何框架、打包工具或 CDN 依赖。数据上用的是浏览器 localStorage，以 JSON 序列化存储，另外提供导入导出备份通道。

为什么最终选择原生加单文件，而不是最初的 React 加 Supabase 方案？React 方案功能更完整、支持多人实时同步，但它要求使用者完成 Supabase 建库、RLS 策略配置、GitHub 推送、EdgeOne 绑定域名等一系列账户操作才能跑起来。而“随时可访问和使用”这个要求，在单文件方案下可以压缩成双击打开一个动作。技术选型的改变不是为了更先进，而是为了把使用门槛降到零——一个需要四十分钟配置才能用的合租工具，室友是不会用的。代价也很明确，就是放弃了多设备实时同步，这一点在后文单独说明。

用了什么方法
整个应用的架构方法是单页应用加全量重渲染。全局只有一个 render 函数，任何一次数据变更，无论是记一笔费用、点一次值日打卡还是切换物品状态，都走同一条路径：先修改 state，再 save 写入 localStorage，最后 render 重绘整个界面。界面用字符串模板拼接生成，通过 innerHTML 一次性替换。事件处理采用事件委托，只在根节点挂一个 click 监听器，靠 e.target.closest 找到触发元素并分发，这样每次重渲染后都不需要重新绑定事件，代码量大幅减少。这个方法的优点是状态永远单一可信，不会出现界面显示和数据存储不一致的情况；缺点是每次操作重绘全页，但对六人合租这种数据量级完全无感。

费用模块的核心方法是债务简化算法。最麻烦的不是记录，而是月底谁该转给谁多少。如果四个人互相垫付了十笔钱，两两结清可能需要十几笔转账。项目采用贪心配对：先遍历所有未结清费用算出每个人的净余额，正数为应收、负数为应付；再把余额拆成债权人列表和债务人列表，各自按金额从大到小排序；然后每次取最大的债权人配最大的债务人，转两者中较小的金额，扣减后继续，直到两边归零。结果是用最少的转账笔数让所有人账目归零，四人场景下通常能把十几笔压缩到两三笔。这不是追求数学最优，而是用贪心取得足够好且人人看得懂的解。

值日模块的核心方法是以分钟为单位的均衡排班。排班最容易犯的错是每人分一样多的任务，但扫地五分钟和擦厨房三十分钟并不等价。项目用任务预估分钟数作为公平的计量单位：每个清洁任务登记时标注预估用时；自动排班时任务按用时从长到短排序，依次分给当前累计负荷最小的成员；排班前先继承上周的负荷作为起点，这样上周干得多的人本周自然少分，实现轮换效果。这套逻辑实现的是长任务优先加最小负荷优先的贪心分配，同时兼顾了周与周之间的公平延续。

四个模块共享同一个产品信念：合租矛盾的本质不是算不清，而是不相信，因此要用记录替代记忆。费用记录带垫付人、分摊人和结清状态，任何争议可回溯；值日打卡带完成时间戳，形成可查的清洁历史；公共物品强制区分公共与个人，从源头切断边界纠纷；公约条款带版本号和逐人确认记录，修改内容时自动升版本并清空确认，杜绝单方面改规则。

最终达成了什么目的
功能上，四个模块形成了完整闭环。概览页一屏回答四个问题：我这周要做什么、谁欠我多少、什么东西该买了、有没有公约等我确认。费用模块支持记一笔、自动算余额、输出最少转账方案、标记结清，全程留痕。值日模块支持任务库维护、一键自动排班、完成打卡、本周每人负荷可视化。物品模块支持公共与个人分类登记、三档状态切换，低库存会自动出现在概览提醒里。公约模块支持分类条款、版本管理、成员逐个确认，修改后自动升版并清空确认。设置页则负责室友增删改、空间改名、数据导出导入备份和清空数据。

体验上，一个文件随处可用。零安装，双击 roommate.html 即可使用，手机浏览器同样正常；零成本上线，拖进 Netlify Drop 几秒得到网址，上传到 EdgeOne Pages 或 Vercel 或 GitHub Pages 并绑定自定义域名即可获得域名固定的长期访问入口；零流量消耗，所有数据在本地，没有网络请求，地铁里、断网时也能记账打卡
